== Project Structure

`doc-example` is a *standalone* doc-only project. It is a single
Maven module that inherits from `ike-parent` and consumes the IKE
documentation pipeline as released artifacts from Nexus. It is not
a reactor and does not aggregate other modules — the comprehensive
renderer/pipeline test surface comes from a single
`src/docs/asciidoc/` tree exercised against every supported PDF
backend.

=== Inheritance

[source]
----
network.ike.platform:ike-parent (released to Nexus)
            ↑
network.ike.examples:doc-example (this project)
----

`ike-parent` provides:

* AsciiDoc rendering pipeline configuration
  (asciidoctor-maven-plugin, multi-renderer PDF wrappers, Kroki
  integration, theme/font/XSL artifact unpacks).
* Java toolchain configuration for hybrid modules (compiler,
  surefire/failsafe, JPMS, javadoc, signing). Doc-only modules
  ignore these but inherit them harmlessly.
* Plugin and dependency version management for the IKE ecosystem
  (`ike-doc-maven-plugin`, `koncept-asciidoc-extension`,
  `minimal-fonts`, `docbook-xsl`, etc.).

There is no separate `java-parent`; an earlier revision of the
ecosystem split Java vs. doc concerns across two parents, but the
post-`IKE-Network/ike-issues#216` topology consolidates both into
`ike-parent`.

=== Packaging shape

`doc-example` declares `<packaging>pom</packaging>` post-`IKE-Network/ike-issues#321`.
The AsciiDoc source payload is auto-attached as
`<classifier>adoc</classifier><type>zip</type>` by
`maven-assembly-plugin` running in `ike-parent`'s `doc-pipeline`
profile (which activates path-conditionally on
`src/docs/asciidoc/` existence). Renderer outputs (PDF, HTML)
attach as additional classifiers when their toggles are enabled.

This shape applies uniformly to doc-only modules and to hybrid
modules (Java code that also ships reference docs); the only
difference is the primary packaging type — `pom` for doc-only,
`jar` (or `maven-plugin`, etc.) for hybrid.

=== Ecosystem context

`doc-example` is one of three reference projects in the IKE
ecosystem:

[cols="2,1,3"]
|===
| Project | Repo | Role

| `doc-example`
| `IKE-Network/doc-example`
| Standalone doc-only consumer of `ike-parent`. Comprehensive
  renderer/pipeline test vehicle. Template for new documentation
  projects.

| `example-project`
| `IKE-Network/example-project`
| Standalone hybrid consumer (Java code + reference docs).
  Demonstrates `<packaging>jar</packaging>` with the doc-pipeline
  profile auto-activating on the side.

| `ike-example-ws`
| `IKE-Network/ike-example-ws`
| Workspace integration test harness. Composes `doc-example` and
  `example-project` via `ws:init` and exercises workspace-layer
  goals against a real multi-repo scenario.
|===

The upstream IKE plumbing repos (`ike-tooling`, `ike-docs`,
`ike-platform`) provide the parent POMs, BOMs, and plugins that
this project consumes. They release independently to Nexus on
their own cadences.

=== Build

Single-command build of HTML + the default PDF renderer:

[source,bash]
----
mvn clean verify
----

Activate additional renderers via property toggles:

[source,bash]
----
mvn clean verify -Dike.pdf.prawn -Dike.pdf.fop
----

See "`Renderer Pipelines`" in the project site index for the full
toggle matrix.
